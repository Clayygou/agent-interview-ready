# 09 · 难度阶梯、题库与自适应提问

> 加载时机：**步骤 8 开始前**（仅交互版）。紧凑版不读本文件。
> 目标：面试过程循序渐进 —— 业务面首题从**基础八股池**随机抽，HR 面从 **behavior 行为题池**随机抽；之后按上一轮回答的评分与**原话**决定追问 / 升难度 / 降档，越往后越难（同档追满 2 次仍 2~3 分时按 §3.1 试探性升一档），且题型跟着 JD 走。
> 题库正文在 `scripts/question_bank.json`（机器可读）；**题量、评分档位、状态转移、追问上限、首题题组、结束状态的唯一来源是 `scripts/rules.json`**，本文件只解释规则，不再另写一套数字。按当前难度只读对应池，不要在开场把题库整份读入上下文。

## 1. 难度阶梯（L1 → L4）

| 档 | 名称 | 考什么 | 典型问法 | 与评分的关系 |
|---|---|---|---|---|
| L1 | 概念复现 | 定义、组件、边界能不能说清；业务面含基础八股热身、HR 面含行为入门题 | 「…由哪几部分组成」「为什么投这个岗位」 | 只答得出这层 ≈ 1 分档 |
| L2 | 机制与代价 | 为什么这样设计、不加会怎样、代价是什么 | 「为什么必须有 X，去掉会出什么问题」 | 讲清机制 ≈ 3 分档 |
| L3 | 场景权衡 / 故障定位 | 具体场景选型、失败归因与降级 | 「工具返回格式错了，怎么定位并降级」 | 要结论 + 依据 + 可核对证据 |
| L4 | 反事实 / 研究判断 | 条件改变后的重新设计、评估方案、评测偏置 | 「上下文预算减半，架构怎么改，怎么证明改动有效」 | 对应 4 分「完整可讲」 |

- **难度是题目层级，评分是回答质量**，两者不互相替代：L4 题答得浅照样 1 分，L1 题答全了也能 4 分。
- L1 池分三个**题组**（`group`）：
  - `basics` = 8 道基础八股（LLM 自回归、Transformer QKV、位置编码 / RoPE、残差与 Norm、PPO、RLHF 三段式、DPO、解码参数），`kb_source.item_ids` 为空并注明「通用八股，无对应题号」，**禁止编造题号**；
  - `role` = 6 道 Agent 岗概念题，用 `kb_source` 映射 `INTERVIEW.md` 真实题号与标题；
  - `behavior` = 3 道 HR 行为入门题（自我介绍、动机、离职原因），L2 另有 2 道行为题，不出技术细节。
- **首轮固定 L1**，题组由面试类型决定（`rules.json → first_pick_group`）：业务面 `basics`、HR 面 `behavior`。这解决 `04`「HR 面不出纯技术细节」与旧版「全局强制八股起手」的冲突；`--tags behavior` 在 L1 / L2 都有题，不会再抽到空池。
- 每次升档**最多 +1**（含 §3.1 的 `probe`），禁止 L1 直跳 L3；降档只发生在答不上来时。
- 目标轮数、追问上限、评分档位映射、结束状态枚举一律查 `rules.json`：**连续追问 ≤2 次、全场追问 ≤4 次**（旧版「全场 1~2 次」与内置轨迹自相矛盾，已统一）；独立主问 3~5 道，轮数不含开局补问对话框。
- 章 3 的 `### JD 题型映射`：`basics` 题量业务面 ≥3、HR 面 0 下限；HR 面由 `behavior` 题域 ≥2 题约束（见 `10` §3）。

## 2. 首题：可复现的随机抽取

1. 调 `python scripts/pick_questions.py --level L1 --group <basics|behavior> --seed <种子>`；种子用 `YYYYMMDD` + `session_id` 的简短组合，**必须由工具实际执行**，不得口报随机数。
2. 把返回的 `seed` / `group` / `picked.id` 记为台账顶层 `pick_seed` / `pick_group` 与首轮 `bank_id`；校验器 import 同一个 `pick()` 函数按同种子同题组复算，算出别的题即判不合格（S18）。`--self-test` 另有 4 组固定输入 → 固定抽中 ID 的金标准，防止共享实现被意外改动。
3. 抽中的题要落成正文中一道真实的 Q 行：业务面在章 3、标题以 `【基础八股】` 开头；HR 面在行为题对应章节。首轮 `q_ref` 指向它；**题干可以改写得更贴岗位，但不得提前把参考答案写进提问对话框**。
4. 后续轮从相邻档位池按 `escalate_hint` 挑题；换考点时优先加 `--tags <题域>`，让题目落在 `10` 命中的 JD 题域里，仍调用 `pick_questions.py --level L2/L3/L4` 留痕；追问轮不抽新题。
5. 台账 `topic` 必须与题库 `topic` 一致，非追问轮的 `question` 必须与该题考点对应（S33 用中文 bigram 重合校验）；`basics` 题的 `q_ref` 必须指向带 `【基础八股】` 的章 3 题目。
6. 老台账没有 `pick_group` 时按 v1 全池复算并给 warn；新文档一律写 `pick_group`。

## 3. 自适应决策表（每轮结束后立刻执行）

**与 `rules.json → transitions / advance` 完全一致**；脚本 S18 用同一份配置复核动作与得分。

| 上一轮评分 | 下一轮允许动作 | 难度 | 追问依据 |
|---|---|---|---|
| 4 完整可讲 | `advance`（常规升档）或 `hold`（已到 L4） | +1（≤L4）或不变 | 引用回答里最硬的那句证据作为升档理由 |
| 3 有依据缺代价 | `followup` 补代价 / `probe`（追满 2 次时） | 不变或 +1（probe） | 引用回答里**缺的那一块**相关原句 |
| 2 有结论无依据 | `followup` 追依据 / `probe`（追满 2 次时） | 不变或 +1（probe） | 引用结论原句 |
| 1 概念复述 | `followup` 追为什么 / `hold` 换同档场景 / `retreat` | 不变或 −1 | 引用回答里那个名词 |
| 0 未作答 | `retreat` 或 `hold` | −1（最低 L1）或不变 | 引用「未作答」这一事实，不编造回答内容 |

- **常规升档只由上一轮 4 分触发**（旧版「≥3 分」与决策表「3 分先追问」冲突，已统一）；3 分先追问，追到 4 分再 `advance`。
- **动作只能由上一轮评分触发**，不得因为「该升难度了」就无视回答。连续 2 轮 0/1 分时停止升档目标，剩余轮保持当前档并在章 8 写明。
- `retreat` 的前提是上一轮 ≤1 分；降档必须写 `decision.reason`。
- 追问**连续**最多 2 次、**全场**最多 4 次；连续 2 次同档追问后不得继续原地打转，按 §3.1 试探性升一档。
- 选「这题我不会」记 0 分，按上表 `retreat` / `hold` 处理，并立即给该题示范作答（`08` §5.1）。

### 3.1 试探性升档 `probe`

「4 分才升档」会让全程 2 分的场次卡死在 L1，和「慢慢变难」冲突。只开下面这一个口子：

| 项 | 规则 |
|---|---|
| 触发 | 当前档已**连续 2 次** `followup`（两次同档、且第二次指向第一次），上一轮 2~3 分仍没升过档，后面还有轮次，且当前未到 L4 |
| 动作 | `probe`：**换考点**升恰好 1 档（+1），`bank_id` 必须来自新档题库，不标 `followup_of` |
| 依据 | `based_on` 仍是上一轮回答原文连续片段（≥8 字），且原样出现在本轮题干里；题干要写明「换个考点」 |
| 理由 | `decision.reason` 必须含「试探」二字并写清触发依据 |
| 上限 | 整场最多 **2 次** probe；两次之间由「连续 2 次同档追问」天然隔开 ≥2 轮，禁止连续 probe |
| 禁止 | 0/1 分不 probe；4 分走 `advance` 不标 probe；不得跳级；不满足条件时用 `advance` / `hold` 低分升档仍判违规 |
| 之后 | probe 之后回到常规决策表，仍按上一轮评分决定追问 / 升档 / 降档 |

- 脚本侧：S18 只对 `action=probe` 放行低分升档，S28 逐条复核上表；S21 对新台账把「追满 2 次仍原地不动」判 error，老 v1 台账与**提前结束**只给 warn。

## 4. 「根据回答深入提问」的硬证据

追问不是换个更难的题，而是咬住上一轮的原话：

- 台账 `decision.based_on` 必须是**上一轮 `answer` 的原文连续片段（≥8 字）**；
- 该片段必须原样出现在**本轮 `question` 里**（写成「你刚才说『…』，那…」）；
- 追问轮 `followup_of` 指向被追问的轮次 `id`，`level` 不高于被追问轮；
- 上一轮未作答时 `based_on` 只能为空，题干改问具体场景，不得假装有回答可引用；
- 只写「结合你上面的回答继续问」而不引用原句 → 不算深入提问，脚本判不合格。

## 5. 台账字段（在 `08` §4 基础上追加）

```json
{
  "session_id": "demo-session-002",
  "mode": "interactive",
  "started_at": "2026-01-02",
  "pick_seed": "demo-seed-002",
  "pick_group": "basics",
  "ended_reason": "completed",
  "turns": [
    {"id": "M1", "q_ref": "Q3-1", "round": 1, "followup_of": null,
     "level": "L1", "bank_id": "L1-B01", "topic": "LLM 的自回归生成与训练推理差异",
     "option": "直接作答",
     "question": "…", "answer": "…", "answered": true,
     "score": 4, "verdict": "完整可讲", "gaps": ["失败代价与替代方案"], "fix": "…",
     "decision": {"action": "start", "based_on": null, "reason": "题库 L1 八股池随机首题"},
     "domain_ref": "通用八股；本地知识库无对应题号"}
  ]
}
```

- `ended_reason` 枚举：`completed / user_stopped / capability_unavailable / failed`（中文描述如「用户提前结束」「达到目标轮数」也可，校验器归一）。**只有 `completed` 校验目标轮数**；提前结束只校验已发生轮次的合法转移，豁免「必须升到 L3」等整场目标，不补写后续轮次（S32）。
- `level`：`L1`~`L4`；`bank_id`：题库内真实 id（追问轮沿用被追问轮的 id）；
- `option`：`08` §3 四个固定选项之一，**不得出现「口述作答」**；除「这题我不会」外必须有非空 `answer`（S27）。
- `answer` 与章 8 `**回答**` **全文逐字一致**；确需节选时另存 `answer_excerpt` + `answer_excerpt_range`，且节选必须是原文连续片段（S16）。
- `score` / `verdict` 必须满足 `rules.json → score_verdicts` 的固定映射，正文与台账双向一致（S15/S16）。
- `decision.action` 描述的是**本轮为什么会被问出来**：`start`（仅首轮）/ `advance` / `followup` / `hold` / `retreat` / `probe`；**不用 `end` 当动作**。
- 评判（失分点 / 改进口径）必须引用台账 `gaps` 或该轮回答原句（S29）；这只能证明引用关系，**证明不了评语中肯**。
- 字段在**看到回答之后**才写，禁止先排好整场难度轨迹再提问。

## 6. 写入章 8

- 每个 M 行追加难度标签：`**M1｜对应 Q3-1｜第 1 轮｜L1**`。
- 章 8 开头给**难度轨迹表**（轮次 / 难度 / 触发动作 / 得分），列数 ≤4、行数 = 轮数；**首列只写纯轮次数字**（`| 1 | L1 | … |`），与总评表的 `| M1 | … |` 区分。
- 每组六项：回答 / 评分 / 失分点 / 改进口径 / 考点索引 / **示范作答**（`03` §9、`08` §5.1）。
- 总评表里补一句「本场最高难度 Lx，下一场建议从 Ly 起手」；提前结束时改写成「本场在第 N 轮提前结束，最高难度 Lx」。
- 评判仍按 `08` §5 的 0~4 rubric，且必须引用回答原句或台账 gaps。

## 7. 降级与边界

| 场景 | 做什么 | 不做什么 |
|---|---|---|
| 题库文件缺失 / 抽题脚本不可用 | 首轮标 `bank_id=""`，章 8 注明「本场未按题库随机起手」，其余流程照跑 | 不编造 bank_id 与 seed |
| `basics` 池不足 3 题 | 章 3 映射表如实写实际题量，章 0 标「基础题库不足」 | 不把岗位题冒充八股、不伪造 id |
| 用户提前结束 / 最后一轮才得 4 分 | 照实保留已发生轮次，`ended_reason=user_stopped`，章 8 注明提前结束 | 不补写后续轮次、不伪造升档、不因「未进入 L3」拒绝交付 |
| 0 轮取消 | `ended_reason=failed` 或 `capability_unavailable`，章 8 写明未发生问答 | 不虚构一轮回答凑数 |
| 全程 0/1 分 | 保持 L1~L2 的具体场景题，章 8 如实写「未进入 L3」 | 不为了「看起来循序渐进」硬升难度 |
| 同一档连续追问 2 次仍是 2~3 分 | 下一轮按 §3.1 用 `probe` 换考点升一档，题干仍引用上一轮原句 | 不继续同档追问、不用 `advance` 伪装、不跳级 |
| 用户要求直接看答案 | 先给本题评判、改进口径与示范作答再继续 | 不提前展示其余题的参考答案、不展示整份题库 |

**已知边界**：难度与评分仍是模型判断，脚本只验「轨迹符合决策表、追问引用了回答原句、首题随机可复现、选项在白名单」，证明不了对话真实发生，也证明不了答案相关、评分准确或经历属实 —— 与 `evidence` / `interview-log` 的边界同源。

## 8. 与 JD 题型映射的关系

`10-jd-profile.md` 决定**文档里出哪些题域**，`09` 决定**模拟面试按什么顺序问**。两者通过 `domain_tags` 打通：

- 业务面：章 3 映射表里 `basics` 的 Q 题号，就是交互版开局的候选池；
- HR 面：开局用 `behavior` 池，章 3 映射表也以 `behavior` 为主，不出技术八股；
- 升档换考点时用 `--tags multimodal` / `--tags agent` / `--tags behavior` 等，从命中题域里抽；
- 面试类型是 HR 面时，L2 以上也只问业务理解与行业判断，不出纯技术细节题（`04` §3）。
