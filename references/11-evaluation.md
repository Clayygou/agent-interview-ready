# 11 · 评测与验收（何时读：需要回归 / 验收 / 改规则）

> 本文件不是生成流程的一部分，单场面试不必读。
> 目的：把「校验通过」与「内容质量好」分开记录，并说明当前证据到哪里为止。

## 1. 三种状态，不要互相代替

| 状态 | 谁给 | 验什么 | 当前手段 |
|---|---|---|---|
| `structure_status` | `validate_doc.py` 退出码 | 章节、题量、字数、引用编号、来源主机、回答全文一致、评分映射、状态转移 | 确定性检查，S0~S34 |
| `content_review_status` | 模型勾选 + 人工标注 | 是否回答本题、证据是否支持主张、评分是否中肯、JD 重要职责是否覆盖 | `07` §2；**尚无人工标注集** |
| `provenance_status` | 用户本人确认 | 每句「我做过」是否能在简历 / 作品集找到出处，教学示例有没有被写成本人经历 | `04` §7、`06` §2；**尚无自动化** |

「脚本 0 error」只能证明第一行。`examples/` 与 `--self-test` 里的夹具是**结构夹具**（同一段参考答案复用于不同题目），可以用于测解析器，不能当作「答案正确」的正例。

## 2. 能力边界与后续方向

1. **可靠性**（已实现）：回答全文比对、题目 / 评分 / 编号绑定、URL 主机名校验、平台别名归一去重、日期上下限与类型预检、提前结束豁免、题库题号—标题核对、每题固定字段。
2. **规则统一**（部分实现）：题量矩阵、评分档位、状态转移、追问上限、首题题组、结束状态集中到 `scripts/rules.json`，校验器载入并覆盖内置默认值；HR 面改用 `behavior` 池；跳题 / 提示 / 不会 / 作答拆成内部事件；追问口径改为「连续 ≤2、全场 ≤4」；不再允许减题。**尚未落地**：用结构化中间数据渲染 Markdown（当前仍是提示词直接写 Markdown + 单行字段解析），中英双语渲染、多行答案也留待这一阶段。
3. **效果验证**（待建设）：需要真实 JD 与简历评测集、人工标注的评分与事实归属，以及首次提问耗时测量。延迟、跨模型稳定性与评分准确性尚未测量，不得声称已验证。

## 3. 真实任务评测集规格（待用户数据填充）

每条样本一个目录，最少包含：`input.md`（公司 + 完整 JD + 面试类型）、`resume.md`（真实简历，敏感字段脱敏）、`expected.json`（期望触发、必考 JD 职责、人工标注的评分档位、已知真实经历清单）。

建议覆盖 11 类场景：工程业务面、HR 面、研究岗、项目稀少的转岗者、短 JD、无联网、缺简历、中途结束、跳题与提示、英文诉求、知识库缺失。

| 指标 | 怎么测 | 当前状态 |
|---|---|---|
| 触发准确率 | 给定输入是否走对 Skill / 面试类型 / 题组 | 未测（需样本） |
| 任务完成率 | 是否交付单个 `.md` 且 `structure_status` 通过 | 已有结构回归 |
| 个人事实有来源 | 逐句比对 `provenance_status`，统计「无出处第一人称句」 | 未测（需真人简历） |
| JD 重要职责覆盖 | `expected.json` 的职责 vs 章 3 映射表与题目 | 未测 |
| 评分准确性 | 模型评分 vs 人工标注，算一致率与偏差方向 | 未测 |
| 首次提问耗时 / 完成率 | 从输入到第一个对话框、到是否跑完整场 | 未测 |

## 4. 可复跑的验收命令

```bash
# 内置：合规夹具 + 反例 + 题库引用 / 固定抽题金标准
python scripts/validate_doc.py --self-test

# 对具体交付物做结构校验
python scripts/validate_doc.py "XX公司_AI Agent工程师_面试准备.md" \
  --evidence evidence.json --interview-log interview-log.json
```

新增用例要与生成器分开维护，并配几组固定输入 / 固定抽中 ID 的金标准，避免生成器与校验器共享同一个错误理解。外部压力测试的数字不能推导日常失败率。

**回归闸门的一条硬规则**：S0 输入预检一旦早退，后续所有检测都不执行。只过滤新规 error 的回归脚本会把早退伪装成「校验器放行」，因此 S0 必须参与判定；新增输入类型规则时要同步跑旧对抗集。「日期未知」（未标注 / 未知 / N/A）是合法哨兵，不等于「日期非法」，两者必须分开处理。

## 5. 已知限制（诚实清单）

- evidence 由模型转录，**不能证明真实工具调用**；「跨平台 ≥2」也不能证明两篇文章独立（可能转载），只能排除同一 URL / 同一别名。
- `point_links` 由 evidence 提供，脚本只核对标签是否落在关联 Q 编号上，不判断考点语义是否对应。
- 回答全文比对只保证文档与台账一致，**不能证明回答确实来自对话框**。
- S29 只验评判是否引用 `gaps` / 回答原句，不评判评语是否中肯。
- 评分 rubric、难度档位仍是模型判断，脚本只验状态转移自洽。
- 英文产物、跨模型稳定性、首次提问耗时未测；`05` 已把「整体英文」降级为「只翻译正文」。
- 修复重跑必须设停止条件：连续两次无改善就保留诊断并交付未通过的草稿，不靠补写事实过检。
