# 07 · 交付前自检

> 加载时机：步骤 10。
> 顺序：**先跑脚本 → 修完所有 error → 再勾语义项 → 复跑脚本 → 交付**。
> 不得靠这份清单自我判定「已通过校验」；通过与否以 `validate_doc.py` 的退出码为准。
> **校验通过只代表 `structure_status` 通过**；`content_review_status`（答案相关性、评分中肯度）与 `provenance_status`（经历真实性）另评，见 §2 与 `11-evaluation.md`。

## 1. 脚本验（确定性，退出码 0 才算过）

| # | 检查项 |
|---|---|
| S0 | 输入预检：evidence / log 根与成员类型、日期合法性（`未标注` 等**日期未知哨兵合法**，`2026-99-99` 判错）、score 为 0~4 整数 → 返回结构化 JSON 错误，不抛 traceback；失败时整份早退，须先排除 S0 再谈其他章节 |
| S1 | 章 0~8 与附录标题齐备、顺序固定，标题层级 ≤3 |
| S2 | 头部含面试类型（**枚举 业务面 / HR 面**，非法值判 error）与 `YYYY-MM-DD` 生成日期，含状态行 |
| S3 | 全文有效字数 8,000~13,000（材料不足 7,000~8,000 为 warn）；**不靠减题压字数** |
| S4 | 各章题量落在 `rules.json → question_counts`，Q 编号章内连续、章节号一致 |
| S5 | 单题有效字数不超 `03` §3 上限，方案设计题 ≤450 且最多 2 道；章末引用块 / 分节线不计入单题 |
| S6 | 各章字数落在预算区间；单章超上限 2 倍判 error（注水）；区间外偏差 warn |
| S7 | 正文 `[n]` 与附录编号一致、连续、≤20 条，两组齐备；每条来源含链接（或「未附链接」）与日期（或「未标注」）；附录孤立来源给 warn，人工确认是否为备用来源 |
| S8 | `【面经高频】` ≤5 且**只打在 `evidence.point_links` 关联的 Q 编号上**；无证据 / 无高频点时全文无该标签、无「据面经」 |
| S9 | 状态行 N 与 items 数一致；平台归一化后集合一致；状态行含 `（平台；起 ~ 止）` 窗口且覆盖每条日期；附录每条的 URL / 标题 / 日期 / 平台与 evidence 一致 |
| S10 | URL 用 `urlsplit().hostname` 精确或合法子域匹配（禁字符串包含）；平台别名归一后按规范 URL 去重；日期在近 18 个月窗口且**不晚于检索日期**；高频考点跨 ≥2 个独立平台 |
| S11 | 表格 ≤4 列、正文无 `####` 四级标题、无 CSS / 内联样式 / 外部图片；代码块内示例跳过 |
| S12 | `🔴` / `🔵` 均带文字标签；文件名含 `_面试准备`（允许 `_probe样例` 等后缀） |
| S13 | 交互版必须有章 8 且每组六项齐全；紧凑版不得有章 8 |
| S14 | M 编号连续，`q_ref` 指向真实存在的 Q 行；总评表与下轮复习项齐备 |
| S15 | 评分 0~4 合法，`score ↔ verdict` 满足 `rules.json → score_verdicts` 固定映射；未作答必须 0 分 |
| S16 | 章 8 回答与台账 **全文逐字一致**（或用带范围的 `answer_excerpt`）；轮数、评分、verdict、id、q_ref 双向一致 |
| S17 | 交互版头部 `> 模式：交互版`；紧凑版 `> 模式：紧凑版` 且章 0 标注未进行模拟面试 |
| S18 | 每轮 `level` ∈ L1~L4；首轮 L1 且 `bank_id` / `pick_seed` / `pick_group` 可复算；升档最多 +1；**动作与 `rules.json → transitions` 一致，常规升档只由 4 分触发** |
| S19 | `decision.action` 由上一轮评分推导；降档需理由；低分升档只能走 S28 的合规 `probe`；追问 `based_on` 是上一轮回答原文片段且出现在追问题干里 |
| S20 | 章 8 每个 M 行带难度标签且与台账一致；难度轨迹表行数 = 轮数、动作与 `decision` 一致 |
| S21 | **若还有下一轮**，4 分后的动作必须是 `advance` 且难度提升；整场完成时最高难度有下限；连续追问 ≤2、全场追问 ≤4；新台账「同档追满 2 次仍 2~3 分」须用 `probe`（老 v1 / 提前结束仅 warn） |
| S22 | 章 3~6 每题 `**参考答案**` 是一整行完整作答：≥100 字、≥2 个编号分点、无占位词；证据锚 / 代价锚缺失给 warn |
| S23 | 交互版章 8 每组有 `**示范作答**`：≥100 字、无占位词、不与用户回答雷同 |
| S24 | 头部 `> 简历状态：` 三态合法；章 4 有修改清单；真实简历 ≥3 条含 `**改法**` / `**对应 JD**`，占位 / 未提供有边界说明 |
| S25 | 章 3 有 `### JD 题型映射` + `> JD 指纹：`（≥3 关键词）；题量 = Q 编号数，编号并集 = 章 3 实际题目，题域 ≥2 |
| S26 | `basics` 题标题带 `【基础八股】`；首题 `pick_group` 按面试类型（`业务面=basics` / `HR 面=behavior`）且 `bank_id` 属于该池 |
| S27 | 台账每轮 `option` 在四个固定值内、不含「口述」；「这题我不会」= 0 分未作答，其余选项必须有非空文本 |
| S28 | `probe` 逐条合规：连续 2 次同档追问、上一轮 2~3 分、升幅恰好 +1、换 `bank_id`、`reason` 含「试探」、`based_on` ≥8 字原句且出现在题干、不标 `followup_of`、整场 ≤2 次 |
| S29 | 每组评判（失分点 / 改进口径）必须引用台账 `gaps` 或该轮回答原句——**只验引用关系，不验评语中肯** |
| S30 | 每题固定字段齐全：章 3~6 的 意图 / 框架 / 参考答案 / 优先级，章 7 的 为什么问 / 优先级 |
| S31 | 题库 `kb_source.item_ids` 与 `expected_titles` 逐条匹配本地 `INTERVIEW.md` 原文（`--self-test` 中执行，知识库不可用则跳过） |
| S32 | `ended_reason` 归一为 completed / user_stopped / capability_unavailable / failed；**只有 completed 校验目标轮数**，提前结束豁免整场目标，1 轮却标「达到目标轮数」判不合格 |
| S33 | 非追问轮 `topic` 与题库一致、`question` 与考点对应（bigram 重合）；`basics` 题的 `q_ref` 指向章 3 基础八股题 |
| S34 | 非真实简历下，`code/` 与第一人称完成式同句时给 warn（教学示例 ≠ 本人经历） |

## 2. 模型勾 / 人工确认（语义与事实）

**触发准确性与内容质量**

- [ ] 四项必填齐全；缺失时只一次性追问，未追问可选项；**缺简历默认暂停**，仅用户明确要求无简历练习才降级；
- [ ] 面试类型已归一化；HR 面未出现技术八股题、首题来自 `behavior` 池；
- [ ] **JD 指纹取自 JD 原文**，题域配比与章 3 实际题目内容相符，没有复用别的 JD 的映射表；
- [ ] 每题参考答案**真的回答了本题**，证据支持主张，代价 / 边界写到了；不是把同一段通用答案换个标题复用（内置结构夹具做不到这点）；
- [ ] 章 6 的补足动作**有证据才写已完成**，否则写「拟补足计划」并列出待确认前提；
- [ ] 招聘方自述与第三方登记的冲突已分别标注，未核实项未写成事实；
- [ ] 至少 2 道业务题结合该公司具体产品 / 业务场景；章 1 覆盖 7 项与近 12 个月动态；
- [ ] 章 2 两版事实一致、口语可朗读；章 4 引用真实项目名与数据，含 1~2 个深挖预埋；
- [ ] Gap 清单实际落到章 2 支撑点、章 4 追问方向、章 6 题目；面经结论改变了章 3 排序与标签；
- [ ] 考点清单外没有出题，同一考点最多出现 1 次；全文无虚构事实，未核实 / 未检索到 / 已脱敏 / 信息边界均已标注。

**经历真实性（provenance）**

- [ ] **逐句确认**：写「我做过 / 我负责过 / 我过往项目」的地方，都能在本人简历或作品集里找到出处；
- [ ] `code/*.py`、知识库 README、示范作答全部以「这个演示实现里 / 教材里的机制」表述，没有改写成第一人称履历；
- [ ] 假设方案写「如果由我实现，我会」，没有写「已完成的补足动作」或编造上线数据；
- [ ] 简历修改清单只调整表达与证据口径，未新增经历、任职单位、年限与业绩数字；
- [ ] 占位 / 未提供简历时章 0 已标注，全文无虚构任职单位 / 年限 / 业绩数字。

**交互与评分**

- [ ] 提问对话框只给题干，未夹带参考答案 / 框架 / 考点提示；固定四选项，没有「口述作答」占位项；
- [ ] 只选选项无文本的轮次已重问而非记分；**连续两次无文本不自动转录成「这题我不会」**；「换一道题」是显式事件，不要求先回答原题；
- [ ] 章 8 回答原文来自对话框、全文一致；未作答记 0 分；评判引用了 `gaps` 或回答原句，**评语中肯度人工复核**；
- [ ] 首题确由 `pick_questions.py` 实跑抽出，seed / pick_group / bank_id 已记入台账；
- [ ] 每轮难度由上一轮回答决定；评分与人工标注是否接近（有标注集时）；追问题干引用回答原句；
- [ ] `ended_reason` 与实际结束方式一致；提前结束没有补写轮次；
- [ ] 交互记录仅本地保存，未进入任何 git 仓库。

**交付形态**

- [ ] 仅一个 `.md`，无外部依赖，手机端无横向滚动；无章首摘要 / 章末速记 / 记忆锚点 / 客套铺垫；
- [ ] 交付话术没有把「校验通过」说成「内容质量已验证」。

## 3. 交付话术（一句话）

`文件位置 + 面试类型口径 + 模拟面试得分概览（紧凑版写「未进行模拟面试」）+ 校验结果（通过 / 有 N 条 warn）+ 一句内容边界提示`。不额外输出摘要长文，不复述文档内容。

## 4. 失败记录与停止条件

- 若脚本反复在同一项报错，优先改 `SKILL.md` 的硬约束或对应 reference，再重跑；**不要**为了通过而放宽校验阈值或伪造 evidence。
- **自动修复连续两次仍不改善 → 停止**：保留真实数据与诊断，明确交付「未通过的草稿」或报告阻塞原因；用户中断、输入不可得、规则本身矛盾时尤其不能靠补写事实过检。
- 若怀疑是规则配置漂移，先查 `scripts/rules.json` 与 `validate_doc.py --self-test`，再用独立维护的外部用例复验。
