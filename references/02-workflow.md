# 02 · 工作流、硬约束与检索证据

> 加载时机：步骤 2~6。正文生成后不必再读。
> 目标：让每一步的产物**强制传导**到最终文档，并让「检索过」变成可核对的证据，而不是一句自述。

## 1. 十步流水线（紧凑版跳过第 8 步）

| # | 动作 | 输入 | 产物 | 失败分支 |
|---|---|---|---|---|
| 1 | 输入校验与归一化 | 用户输入 | 输入状态表 | 缺失 → 对话框一次问清并停（01 §6、05） |
| 2 | 拆 JD + 抽指纹（`10`） | JD 文本 | 硬性 / 隐性要求、≥8 个高频关键词、**JD 指纹四段**、汇报关系与协作对象、考核重点 | JD 过泛 → 标注并走岗位类别默认画像 |
| 3 | 面经检索与证据落盘 | 公司 + 岗位 + 类型 | `evidence.json` 或「未检索」结论 | 无工具 / 无结果 → `found=false`（05） |
| 4 | 公司与行业调研 | 公司名 + 检索能力 | 7 项事实、近 12 个月动态、3~5 条可说出口的公司理解 | 公开信息少 → 标信息边界（05） |
| 5 | 匹配度 / Gap 分析 | JD + 简历 | 高度匹配 / 勉强匹配 / 明显缺失 三张清单 | 无硬性 Gap → 选影响胜任度最大的软性差距 |
| 6 | 定题量与考点分配 + **JD 题型映射**（`10`） | 类型 + 面经 + Gap + JD 指纹 | 题量表 + **章 3 映射表（题域 / 题量 / Q 编号）** + 去重后的考点清单 | 与字数上限冲突 → 字数优先，减低概率题 |
| 7 | 生成章 1~7：映射表、**业务面 ≥3 道基础八股**、每题**完整示范作答**、**简历针对性修改清单**（参考答案暂不展示） | 上述全部 + 简历三态 | 逐章内容 | 见 `03` / `04` / `10` |
| 8 | 交互模拟面试（自适应）：**按面试类型从 L1 basics / behavior 池随机首题** → 固定四选项对话框 → 评分 → 依决策表追问 / 升档 / 降档 / **`probe` 试探性升档** → 循环至目标轮数或用户提前结束 | 题目清单 + 每轮回答 | `interview-log.json`（逐轮回答、**option**、评分、难度轨迹与决策依据） | 用户跳过 / 对话框不可用 → 切紧凑版（05、08、09） |
| 9 | 排版、事实标注，把章 8（含每题**示范作答**）并入同一份文档 | 逐章内容 + 评判 | 可朗读稿 | 见 `03` / `06` / `08` |
| 10 | 脚本校验并交付 | 文档 + evidence + log | 校验报告 + 单个 `.md` | 非 0 退出码 → 修复重跑；连续两次无改善即停止，交付未通过的草稿并说明阻塞原因 |

## 2. 核心约束：分析必须改变输出

**只罗列不使用的分析、检索到面经却不改变题目、Gap 清单与章 6 对不上，均视为不合格。**

| 中间产物 | 必须落到 | 具体传导方式 |
|---|---|---|
| 高度匹配清单 | 章 2 自我介绍 | 每个支撑点对应一条高匹配项，并嵌入 JD 关键词 |
| 勉强匹配清单 | 章 4 简历深挖 | 被追问方向优先落在「勉强匹配」的项目细节与职责边界 |
| 明显缺失清单 | 章 6 Gap 质疑 | 每个主要 Gap 一题，硬性 Gap 至少 1 题 |
| JD 高频关键词 | 章 2 / 章 3 / 章 4 | 自我介绍自然嵌入；**落成 `### JD 题型映射` 的指纹与题域配比**；简历修改清单每条的「对应 JD」要对得上 |
| **JD 题型映射** | 章 3 全部题目 | 映射表 Q 编号并集 = 章 3 实际题目；`basics` ≥3 题且标题带 `【基础八股】`；题目内容与题域相符 |
| **简历三态** | 章 4 修改清单 | 真实简历 → ≥3 条逐条改法；占位 / 未提供 → 明确边界说明，不编造经历 |
| 面经高频考点 | 章 3 排序与标签 | 提到「高」概率、加 `【面经高频】`，最多 5 道 |
| 公司调研 7 项 | 章 1 + 章 3 | 至少 2 道业务题结合公司具体产品 / 业务场景 |
| 模拟面试评判 | 章 8 | 每轮回答原文、评分、难度、失分点、改进口径、**示范作答（这题没有问题的真实回答）**逐条写入；难度轨迹表落到「下一场从哪档起手」；总评表落到 3 条下轮复习项 |
| 上一轮回答 | 下一轮题目 | 评分决定追问 / 升档 / 降档；同档追满 2 次仍 2~3 分走 `probe` 试探性升一档；追问题干必须引用上一轮回答原句，不得预先排好整场轨迹 |
| 对话框选项 | 台账 `option` | 四个固定值；只选选项无文本 → 重问同题，不记分；「这题我不会」→ 0 分 + 立刻给示范作答 |

## 3. 题量矩阵（硬约束）

**题量矩阵、评分档位映射、状态转移、追问上限、首题题组、结束状态一律以 `scripts/rules.json` 为准**；下表只是它的可读投影，改数字先改配置再跑 `--self-test`。

| 面试类型 | 章 3 业务题 | 章 4 简历深挖 | 章 5 行为题 | 章 6 Gap | 章 7 反问 |
|---|---|---|---|---|---|
| 业务面 | 8~10 | 6~10 | 4~6 | 1~3 | 4~6 |
| HR 面 | 3~5 | 5~7 | 7~10 | 1~2 | 4~6 |

- 章节数量与顺序**不因类型增删**，只调题量、单题详略与侧重。
- 用户要求「更详细」时：在矩阵**上限内**加题、把调研写到预算上限，**不得突破** 13,000 字硬上限。
- **题量矩阵固定，不允许为压字数减题**：超预算时压缩单题表述，材料不足在章 0 标注信息边界并接受字数 warn；脚本不识别「获准减题」例外。
- 矩阵与字数上限冲突时：**字数上限优先**，从低概率题开始减 1~2 道，并在章首一句话注明取舍。

## 4. 题目去重

生成前先列「考点清单」，清单外不得出题，**同一考点最多出现 1 次**。

| 章节 | 只考什么 | 不考什么 |
|---|---|---|
| 章 3 业务能力 | **基础八股热身**、按 JD 题域分配的岗位能力、公司业务场景 | 简历中已写项目的复述、与映射表题域无关的题目 |
| 章 4 简历深挖 | 简历 / 作品集里的事实细节、个人贡献 | 与简历无关的通用业务题；`### 简历针对性修改清单` 是「怎么改简历」，不是题目 |
| 章 5 行为面试 | 软素质、动机、协作方式 | 项目技术细节与业务方案 |
| 章 6 Gap 质疑 | 画像与硬性条件的差距 | 前三章已覆盖的题目 |
| 章 7 反问 | 低风险、能加分的信息缺口 | 薪资、加班、官网可查的浅层信息 |

- 章 3 与章 4 不得共用同一项目案例：章 3 引用公司业务场景，章 4 引用候选人经历。
- 确需换角度复用（如「项目难点」）：章 4 只给 1 句解释口径，章 6 才展开完整回答，且问题形式必须不同。

## 5. 面经检索与证据契约

**检索时机**：JD 拆解后、公司调研前。先找同公司 / 同岗位 / 同类型的近期面经，不用通用面经充数。

- 平台：小红书、知乎、抖音、牛客、脉脉、看准网；海外岗可加 Glassdoor、Blind。
- 关键词：`{公司} {岗位} 面经`、`{公司} 面试 流程`、`{岗位} 一面 / 二面`、`{公司} HR 面`；全称与简称都试。
- 时间：优先近 12 个月，最长 18 个月；更早的只参考流程，不参与「高频」判断。
- 提取：轮次与流程、题型与题量、重复考点、考察重点、收尾方式。**不提取薪资、八卦、面试官个人信息**。
- 可信度：同一考点出现在 **≥2 个独立平台来源** → 记为「面经高频」；单一来源标「单一来源」；官方流程与个人回忆冲突以官方为准。
- 使用：只调题目概率排序、详略与标签；**不改题量矩阵、不覆盖 JD 硬性要求**。概率优先级 `面经高频 > JD 推断 > 通用经验`。
- 版权与隐私：转述要点，不复制大段原文，不引用可识别个人的信息。

### evidence.json（唯一可信的检索凭证）

```json
{
  "searched_at": "2026-01-01",
  "tools_used": ["web_search"],
  "queries": ["{公司} {岗位} 面经"],
  "found": true,
  "items": [
    {"platform": "牛客", "title": "…", "date": "2026-09-12",
     "url": "https://…", "points": ["ReAct 循环", "工具参数校验"]}
  ],
  "high_frequency_points": ["ReAct 循环"]
}
```

- 由**真实工具调用结果**写入，不是模型凭印象生成。没有检索工具 / 没调用成功 / 结果全过期 → `found=false`、`items=[]`、`tools_used=[]`。
- **「同公司 / 同岗位 / 同类型」是或关系，但需限定**：同类型 = 同岗位族 + 同轮次 + 近 18 个月；目标公司 0 条面经而采用其他公司同岗位面经时，章 0 必须标「非目标公司面经，仅作题型参考」，且**不得**把通用面试题聚合站（题库、SEO 站）当独立平台面经充数。
- `platform` 只取 §5 白名单内的值（牛客 / 知乎 / 小红书 / 抖音 / 脉脉 / 看准网；海外岗可加 Glassdoor / Blind），且 **URL 域名必须与该平台对应**；`date` 为 `YYYY-MM-DD` 且落在近 18 个月内，无发布日期写「未标注」。
- 脚本会交叉校验：状态行平台集合 = `items.platform` 集合；附录面经每条 URL 与对应 `items.url` 一致；`high_frequency_points` 为空时全文不得出现 `【面经高频】`；每个高频考点必须出现在 ≥2 个**不同 platform** 的 `items.points` 中。
- **检索到面经但全部来自单一平台**：`found=true`、`high_frequency_points=[]`、全文不打高频标签；重复考点按「单一来源」标注，只用于决定详略，不调整概率排序（见 `05`）。
- **已知边界**：契约要求「工具直写」，但当前 evidence 仍由模型按工具结果转录，脚本无法验证是否真有调用日志。彻底防伪造需要检索工具直接写 JSON 并附调用记录；在此之前把 evidence 当可核对台账，不当防伪凭证。
- 章 0 状态行格式固定，脚本按此解析：
  - 有证据：`> 面经检索：找到 N 条（平台 A / 平台 B；YYYY-MM-DD ~ YYYY-MM-DD）`
  - 无证据：`> 面经检索：未检索到有效面经`
- 无证据时全文**不得**出现 `【面经高频】` 标签或「据面经」措辞，也不得写「找到 N 条」。
- 附录「面经」组条目数必须等于 `len(items)`，且 platform / title / date / url 与 evidence 一致。

## 6. 岗位类别 → 考点包

按 `01` 判定的岗位类别，在步骤 7 加载 `04-agent-domain.md` 中对应的题号组；HR 面只取业务理解与行业判断类，不出纯技术细节题，模拟面试首题从 `behavior` 池抽（`rules.json → first_pick_group`）。

**题型配比另走 `10-jd-profile.md`**：步骤 2 抽 JD 指纹，步骤 6 把关键词映射成题域与题量，落成章 3 章首表格。`04` 决定「题目内容从哪来」，`10` 决定「不同 JD 该考哪些题域、各几道」；两者不互相替代。基础八股不来自知识库，按 `09` 的 `basics` 池出题，`kb_source.item_ids` 留空并注明「无对应题号」；岗位题的 `kb_source` 必须与 `INTERVIEW.md` 题号—标题一致，禁止编造。

## 7. interview-log.json（交互问答台账）

第 8 步产出，字段与评分档位见 `08` §4 / §5，难度与决策字段见 `09` §5，`examples/interview-log.example.json` 是格式样例。

- 每轮对话框返回后立即写一条，`answer` 为用户原文；无文字 → `answered=false`、`score=0`。
- `option` 必须是 `08` §3 的四个固定值之一，不得含「口述」；除「这题我不会」外必须有非空 `answer`，否则应重问同题而不是记一轮。
- 四个选项映射为内部事件 `answer / hint / dont_know / skip`（`rules.json → options`）：无文本一律重问同题、不记分、不新增轮次，连续两次无文本也**不自动转录**成「这题我不会」；「换一道题」是显式 `skip`，不要求先回答原题。
- 台账顶层 `ended_reason` 用 `completed / user_stopped / capability_unavailable / failed`（中文描述亦可）；只有 `completed` 校验目标轮数，提前结束豁免整场覆盖目标。
- `q_ref` 必须指向正文真实 Q 行；`score` / `verdict` / `level` / `decision` 在看到回答后才写。
- 顶层 `pick_seed` / `pick_group="basics"` 与首轮 `bank_id` 来自 `scripts/pick_questions.py --level L1 --group basics` 的**实际执行结果**，校验器会 import 同一个 `pick()` 用同种子同题组复算。
- 升档最多 +1：常规 `advance` **只由上一轮 4 分触发**（3 分先追问，追到 4 分再升）；**同档连续追问 2 次仍 2~3 分时走 `probe` 试探性升一档**（`09` §3.1），须换考点、`reason` 含「试探」、不标 `followup_of`，整场最多 2 次；0/1 分仍不许升档。
- 追问（含 `probe`）的 `decision.based_on` 是上一轮回答原文片段（≥8 字），并原样出现在题干里。
- 交付时与 `evidence.json` 一起传给脚本做交叉校验：`--interview-log interview-log.json`。
- **已知边界**：同 evidence，log 由模型按对话框结果转录，脚本只能验一致性，不能证明对话真实发生。
