# 01 · 输入契约

> 加载时机：步骤 1（校验输入）。输入齐全且无歧义时可只读 `SKILL.md` 的摘要。
> 目标：把「什么时候该问、什么时候一律不问」写死，减少无效轮次与幻觉入口。

## 1. 输入表

| 输入 | 必需 | 用途 | 规则 |
|---|---|---|---|
| 公司名称 | 是 | 调研背景、业务、文化、近 12 个月动态 | 有歧义（集团 vs 子公司、同名公司）时以 JD 中出现的主体为准，并在章 0 标注口径 |
| 岗位 JD | 是 | 拆硬性 / 隐性要求、推断考点、定优先级 | 过短或过泛时标「JD 信息不足」，改用岗位类别通用能力命题 |
| 个人简历 | 是 | 自我介绍素材、深挖题、案例与数据、**简历针对性修改清单** | 文件形式先完整解析为文本，保留项目名、起止时间、职责边界、量化结果；解析后判定三态并写进头部 `> 简历状态：`（见 §3 第 8 条） |
| 本场面试类型 | 是 | 决定题量配比、章节侧重、自我介绍口径 | 按 §2 归一化，不追问、不再细分 |
| 案例 / 作品集 | 否 | 补充项目细节与业务题素材 | 缺失时**不追问**、不虚构；文件 / 文本 / 链接均可 |

## 2. 归一化

**面试类型只分两档**（原始表述保留在章 0 元信息里）：

| 用户说法 | 归一化 | 章 0 标注 |
|---|---|---|
| 一面 / 二面 / 专业面 / 技术面 / 业务面 / 主管面 / 总监面 / 交叉面 / 群面 | 业务面 | `业务面（{原始表述}）` |
| HR / 人力 / 综合素质面 | HR 面 | `HR 面（{原始表述}）` |

- 用户同时提到两类：以**先进行的一轮**为主类型，章 0 末尾补 2~3 条另一类的差异提示，不另生成文档。
- **岗位类别**另算一个维度，按 JD 主职责判为 `Agent 工程 / 算法 / 平台后端` 之一；混合岗取「主类别 + 1 条次类别考点」，用于挑考点包（见 `04-agent-domain.md`），**不增加面试类型档位**。

## 3. 七条硬性规则

1. 四项必填齐全 → **直接进入生成流程，禁止追问**薪资、顾虑点、期望风格、目标时长、目标公司偏好等任何补充信息。
2. 仅在缺失时**弹对话框一次问清所有缺失项，问完即停**；不边问边生成，规范见 §6。
3. 可选项（案例 / 作品集）缺失**不得追问**，全文也不得出现「另有作品集」之类暗示。
4. 禁止猜测或编造公司名称、岗位名称、候选人经历；专有名词、技术栈、业务术语**原样保留**，不翻译、不改写。
5. 简历解析失败或为不可识别图片 → 要求提供可复制文本并**暂停生成**，不猜内容。**缺简历默认暂停**；仅当用户明确要求「无简历练习 / 演练」时才允许 `未提供` 降级继续，且章 0 必须标注「演练 / 占位」，不得虚构经历（统一 `05` 与 `03` 的两种说法）。
6. 作品集只取材料中真实存在的内容；与简历对同一项目冲突时**以简历为准并标注「待本人确认」**；客户名、未公开数据脱敏为中性表述后再引用。
7. **简历含占位 / 模板字段**（姓名、学历、任职单位、起止时间为空，或写「占位 / 待填 / 示例」）时不得当作真实经历：章 0 必须标「简历含占位字段」，全文不写具体任职单位、任职年限与业绩数字，章 4 只引用材料中真实存在的项目文件，交付话术提示「需替换为真实简历」。演练 / 试用材料尤其常见。脚本不验此项，属 `07` 模型勾选项。
8. **简历三态必须写进头部**，格式固定为 `> 简历状态：已解析（真实简历）` / `> 简历状态：占位 / 演练代填` / `> 简历状态：未提供`。三态决定章 4 `### 简历针对性修改清单` 的输出：
   - 已解析（真实简历）→ **必须逐条给出针对该 JD 需要修改的地方**（≥3 条，每条含「改法」与「对应 JD」）；
   - 占位 / 演练代填 → 写明「需替换为真实简历」，可给通用改写方向但须标注「非针对本人经历」；
   - 未提供 → 写明「未提供简历，无法给出针对性修改」，并列出拿到简历后优先核对的三处。
   头部缺此行、或真实简历却没给修改清单，脚本 S24 判不合格。**改法只调整表达与证据口径，不虚构经历、数据、任职单位与任职年限**（`06` 事实边界）。

## 5. 与校验脚本的关系

题量、评分档位、状态转移等数字统一在 `scripts/rules.json`，本文件不复写一份。脚本不校验输入契约本身（它看不到对话），但会校验**契约的落地结果**：头部是否有面试类型、生成日期与 `> 简历状态：` 三态行（S2 / S24），章 3 是否有 `### JD 题型映射`（S25 / S26），章 4 是否有 `### 简历针对性修改清单` 且条数与三态匹配（S24），全文是否出现作品集相关虚构表述。语义类检查项在 `07-checklist.md` 由模型勾选。

## 6. 开局对话框规范（交互版）

- 只在「必填缺失且检索工具查不到」时弹出；一次对话框 ≤4 个问题，**问完即停**。
- 能用检索补齐的（公司主体、公开 JD、公开面经）**不问**，先查再判。
- 每题 2~4 个选项；需要长文本时提示「在下方输入框粘贴」，例如简历；拿到简历后立刻判定三态（`08` §2）。
- 开局问题只收集事实、**不出题**，不得包含参考答案或考点提示。
- 开局补问对话框与模拟面试对话框是**两类不同的对话框**：前者只在缺必填信息时出现，选项按需设计；后者固定四个选项（`08` §3），不得出现「口述作答」占位项。四项映射到内部事件 `answer / hint / dont_know / skip`（`rules.json → options`）：无文本一律重问同题、不记分、不新增轮次，连续两次无文本也不自动转录成「这题我不会」；`skip` 换题不要求先答原题。
- 用户选择项里若含推断（如公司主体有歧义），章 0 标「待确认」，不写成已确认事实。
- 交互回答与错题记录只在本地保存，不进 git。
