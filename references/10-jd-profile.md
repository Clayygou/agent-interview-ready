# 10 · JD → 题型映射

> 加载时机：步骤 2（拆 JD）与步骤 6（定题量与考点分配）。紧凑版 / 交互版都要读。
> 目标：**不同 JD 出不同题**，避免一套通用题走天下；映射结果落成章 3 章首的表格，由校验器 S25 / S26 确定性核验。
> 本文件只写映射规则，题库正文在 `scripts/question_bank.json`；题目内容仍按 `04` 的考点包选取。

## 1. 先抽 JD 指纹（步骤 2 产物）

从 JD 原文里抽出四项，写成一行（格式固定，脚本按此解析）：

```markdown
> JD 指纹：示例公司｜AI Agent 工程师｜多模态 / Agentic / 后训练 / 评测｜业务面
```

- 四段依次是 `公司主体｜岗位名｜≥3 个关键词（/ 分隔）｜面试类型`；关键词**只取 JD 中真实出现的词**，不推断、不补词、不翻译。
- 同一家公司不同岗位、或同一岗位不同 JD，指纹与题域组合必须不同；复用上一份文档的映射表视为不合格。
- 指纹行放在章 3 的 `### JD 题型映射` 小节里，不是章 0 元信息。

## 2. 题域字典

题域是题目的机器可读分类，与题库 `domain_tags`、映射表第一列使用同一套枚举。

| 题域 | 命中关键词（示例） | 主要考什么 | 典型题库题 |
|---|---|---|---|
| `basics` | 固定项，不依赖 JD | LLM / Transformer / PPO / RLHF / 位置编码 / 解码等八股 | `L1-B01` ~ `L1-B08` |
| `llm` | 大模型、预训练、SFT、RLHF、微调、对齐 | 训练与对齐机制、代价、失败模式 | `L1-06`、`L3-05` |
| `agent` | Agent、Agentic、工具调用、规划、MCP、Skills | 循环、控制权划分、工具失败降级 | `L1-01` ~ `L1-04`、`L2-01` ~ `L2-03` |
| `multimodal` | 多模态、全模态、VLM、视觉、语音、视频帧 | 上下文预算、模态对齐、跨模态工具链 | `L2-05`、`L3-03`、`L3-04` |
| `rag` | RAG、检索、向量库、重排、知识库 | 切块、混合检索、召回评测 | `L2-04` |
| `eval` | 评测、评估、benchmark、指标、幻觉率 | 指标口径、离线在线对齐、评测偏置 | `L2-06`、`L4-02`、`L4-04` |
| `engineer` | 部署、推理加速、服务化、高并发、状态机 | 幂等、超时、可观测、故障定位 | `L2-03`、`L3-01` |
| `research` | 研究、论文、实验、消融、复现 | 反事实设计、消融与结论边界 | `L4-01` ~ `L4-04` |
| `behavior` | HR 面、综合素质、协作、动机 | 软素质、稳定性、动机（HR 面专用） | 不出技术细节题 |

## 3. 映射规则（步骤 6 产物）

1. 按 JD 关键词命中题域，取权重最高的 **2~4 个题域**进映射表；其余不进表、不出题。
2. 题量分配：业务面章 3 共 8~10 题，HR 面 3~5 题。**业务面 `basics` ≥3 题；HR 面 `basics` 0 下限、`behavior` ≥2 题**（HR 面不出技术细节题）。其余按题域权重分配，单题域 ≤4 题；下限与题量矩阵以 `rules.json` 为准。
3. 每个进表的题域至少 1 题；题域数 ≥2。只覆盖单一题域一律判不合格。
4. 映射表里 `对应 Q 编号` 的并集必须**等于章 3 实际全部 Q 编号**，不重不漏；每行 `题量` 必须等于该行列出的 Q 编号个数。
5. 归入 `basics` 的题目标题必须以 `【基础八股】` 开头（例如 `**Q3-2｜【基础八股】Transformer 自注意力与 QKV 的平方复杂度**`），脚本 S26 会逐条核对。
6. **题目内容要与题域相符**：脚本只能验编号与标记，语义对应由 `07-checklist.md` 的模型勾选项负责。
7. 交互版：首题按面试类型从 `basics`（业务面）或 `behavior`（HR 面）池按种子随机抽（`09` §2 / `rules.json → first_pick_group`）；后续升档换考点（含 `probe`）时优先用 `pick_questions.py --tags <题域>` 从命中题域抽，`behavior` 在 L1 / L2 都有题，不会再出现空池。

## 4. 岗位类别默认画像（JD 信息不足时兜底）

| 岗位类别 | 默认题域（按序） | 业务面 8 题示例配比 |
|---|---|---|
| Agent 工程 | basics / agent / engineer / eval | 3 / 3 / 1 / 1 |
| 算法 · 模型 | basics / llm / rag / eval | 3 / 2 / 1 / 2 |
| 平台后端 | basics / engineer / agent / eval | 3 / 2 / 2 / 1 |
| 多模态 · 研究 | basics / multimodal / llm / research | 3 / 2 / 1 / 2 |
| HR 面 | behavior / eval / basics | 2 / 1 / 0（共 3~5 题，不出技术八股） |

- 命中真实 JD 关键词时**优先用关键词**，默认画像只在「JD 过短 / 过泛」时启用，并在章 0 标「JD 信息不足」。
- 默认画像的指纹关键词段写 `JD 信息不足 / 岗位通用能力 / {类别}` 三项，仍须 ≥3 项，但**不得伪装成 JD 原文**。

## 5. 输出格式（章 3 章首，固定）

```markdown
### JD 题型映射

> JD 指纹：示例公司｜AI Agent 工程师｜多模态 / Agentic / 后训练 / 评测｜业务面

| 题域 | JD 关键词 | 题量 | 对应 Q 编号 |
|---|---|---|---|
| basics | LLM / Transformer / PPO | 3 | Q3-1, Q3-2, Q3-3 |
| multimodal | 全模态 / VLM | 3 | Q3-4, Q3-5, Q3-6 |
| agent | Agentic / 工具调用 | 2 | Q3-7, Q3-8 |
| research | 后训练 / 评测 | 2 | Q3-9, Q3-10 |
```

- 表格固定 4 列，表头与分隔行固定；题域名只能用 §2 枚举里的小写值。
- 该小节写在**第一个 Q 行之前**，属于章级内容，不计入任何单题字数。
- 章 3 题目按映射表顺序排列：业务面先基础八股热身再岗位题；HR 面以行为 / 业务理解题为主，难度由浅入深。

## 6. 反模式

- 所有 JD 复用同一张映射表，或只把公司名换掉；
- 指纹里塞 JD 没出现过的词（编造关键词）；
- 业务面 `basics` 少于 3 道，或 HR 面强行塞技术八股、把八股题标成别的题域；
- 映射表 Q 编号与正文对不上、题量与 Q 编号个数不一致；
- 表写了 `multimodal`，题目却全在问 Workflow 选型（语义不符，脚本验不了）；
- 把题库整份贴进文档或提问对话框。

## 7. 降级与边界

| 场景 | 处理 |
|---|---|
| JD 过短 / 过泛 | 用 §4 默认画像，章 0 标「JD 信息不足」，不编造关键词 |
| 命中题域在题库里没有对应题 | 用 `04` 的知识库题号 + JD 场景命题，`domain_tags` 仍归入该题域，不硬凑别的题域 |
| `basics` 池不足 3 题 | 按 `05` 降级：章 0 标「基础题库不足」，映射表如实写实际题量并说明，不伪造题目 |
| 关键词互相冲突（如同时强调研究与应用） | 按 JD 中**出现位置更靠前 / 职责描述更具体**的一侧定主类别，另一例保留 1 题，章 0 标注取舍 |
| 不同 JD 但题型确实相同 | 允许题域组合相同，但指纹关键词段必须不同，且题目内容要分别贴合各自 JD（`07` 模型勾选项） |
