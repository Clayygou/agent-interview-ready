# 05 · 降级与异常处理

> 加载时机：**任一环节失败时**才读。全链路正常时不要预读（这条本身就是渐进式披露）。
> 三条原则：可降级不可编造；部分结果必须标注边界；失败不静默。

## 1. 场景表

| 场景 | 处理 | 不做什么 |
|---|---|---|
| 四项必填缺失 | 一次问清所有缺失项，暂停生成 | 不追问可选项、不边问边生成 |
| 面试类型是轮次 / 细分叫法 | 归一化为业务面（HR 相关归 HR 面），章 0 记原始表述 | 不追问、不新增档位 |
| 同时提到业务面与 HR 面 | 以先进行的一轮为主，章 0 补 2~3 条差异提示 | 不生成两份文档 |
| 简历解析失败 / 图片不可识别 | 要求可复制文本，暂停 | 不猜简历内容 |
| JD 过短或过泛 | 按岗位类别通用能力命题，章首标注「JD 信息不足」 | 不编造职责与要求 |
| 作品集无法解析 | 说明失败，退回仅用简历 | 不推断内容、不暗示「另有作品集」 |
| 作品集链接打不开 | 按「未提供」处理并说明原因 | 不脑补链接内容 |
| 作品集与简历冲突 | 以简历为准，标「待本人确认」 | 不擅自取舍 |
| 作品集含敏感信息 | 脱敏后引用或略过 | 不做二次推断、不写客户真名 |
| **无检索工具 / 工具调用失败** | `evidence.json` 写 `found=false`、`items=[]`；章 0 写「未检索到有效面经」；退回 JD + 简历 + 公司信息推断 | 不写「找到 N 条」、不写「据面经」、不打 `【面经高频】` |
| 面经不可得 / 互相矛盾 / 全过期 | 仅参考流程，不调整概率 | 不编造面经、不把个人回忆写成公司制度 |
| evidence 与章 0 状态不一致 | 以 evidence 为准改文档，重跑脚本 | 不改 evidence 来迁就文档 |
| 公司公开信息稀少 | 调研取预算下限，标信息边界；结合公司业务的题降为 1 道，其余用行业通用场景并标注 | 不用推测填满、不编财务数字 |
| 无法联网 | 基于已有知识生成，公司动态逐条标「未核实，建议用户核实」 | 不默认旧数据为现状 |
| 本地知识库路径不存在 | 优先按 `AGENT_INTERVIEW_KB` / Skill 同级目录 / 当前目录探测；仍找不到则跳过 `04` 考点包，只用 JD + 岗位通用能力命题，章 0 标注「领域题库未接入」，题号—标题核对跳过 | 不写死用户绝对路径、不编造题号与 `code/` 文件名 |
| 简历与 JD 严重不匹配 | 仍产出文档，提高 Gap 题权重，开头提示匹配风险 | 不拒绝交付、不粉饰匹配度 |
| 完美匹配、无硬性 Gap | 选对胜任度影响最大的软性差距命题 | 不硬凑硬性 Gap |
| 简历缺少可用项目 | 转向职责细节与方法论，提示补充项目细节 | 不虚构项目 |
| 超出字数上限 | 按 `03` 顺序删减，优先保留必背答案与 Gap 题 | 不整体超限、不删章 |
| 脚本校验返回 error | 逐条修复后重跑；**自动修复连续两次仍不改善就停止**，保留真实数据与诊断，交付明确标为未通过的草稿或报告阻塞原因 | 不手写「已通过校验」、不忽略 error、不靠补写事实过检 |
| 文件名非法或过长 | 清洗 `/ \ : * ? " < > |` 为下划线 | 不改交付格式 |
| 用户中途要求英文 | **只翻译正文表述**；章节标题、Q / M 标记、字段名、选项等机器字段保持中文（解析器依赖固定结构），并在章 0 说明 | 不承诺「整体英文产物」、不输出双语版 |
| **检索到面经但全为单一平台** | `found=true`、`high_frequency_points=[]`；章 0 写「找到 N 条（单一平台）」，重复考点标「单一来源」，只调详略不调概率 | 不凑平台、不打 `【面经高频】`、不把题库站当第二个平台 |
| **招聘页 / 官网为脚本渲染，页面原文抓不到** | 只用搜索索引摘要转述，逐处标「摘要转述，未核对页面原文」，章 0 写信息边界 | 不把摘要当原文引用、不补写页面里没看到的字段、不编造链接内容 |
| **简历含占位 / 模板字段** | 按 `01` 第 7 条：章 0 标注，全文不写任职单位 / 年限 / 业绩数字，交付时提示替换 | 不把占位文本写成真实经历、不因「解析成功」就跳过真实性判断 |
| **用户跳过模拟面试 / 要求直接出文档** | 切紧凑版，章 0 标「未进行模拟面试」，不生成章 8 | 不编造问答与评分、不把跳过写成已面过 |
| **对话框不可用 / 中途喊停** | 按 `08` §6 / `09` §7：只保留已发生轮次，`ended_reason` 写 `user_stopped` / `capability_unavailable`，注明最高难度；不可用时切紧凑版 | 不补写未发生轮次、不因「未进入 L3」拒绝交付、不用纯文本提问冒充对话框 |
| **简历为占位 / 演练代填** | 头部写 `> 简历状态：占位 / 演练代填`；章 4 修改清单写明「需替换为真实简历」，可给通用改写方向并标注「非针对本人经历」 | 不把占位字段当真实经历逐条「优化」、不编造任职单位与业绩数字 |
| **未提供简历** | 头部写 `> 简历状态：未提供`；修改清单写明无法针对性修改，并列出拿到简历后优先核对的三处 | 不虚构简历内容、不假装做过匹配度分析 |
| **真实简历但章 4 写不出 3 条改法** | 回到 JD 指纹逐条比对简历段落，至少覆盖「项目结果量化」「技能词与 JD 对齐」「自我评价换证据」三类 | 不降低到 1~2 条、不用「建议优化表达」这类空话凑数 |
| **JD 过短 / 过泛** | 用 `10` §4 岗位类别默认画像，章 0 标「JD 信息不足」，指纹关键词段如实写信息边界 | 不编造 JD 关键词、不复用别的 JD 的映射表 |
| **题库 basics 池不足 3 题** | 映射表如实写实际题量，章 0 标「基础题库不足」，首题从现有 basics 题抽 | 不把岗位题标成 `【基础八股】`、不伪造 bank_id |
| **只选了对话框选项、没有文本** | 重问同题，不新增轮次、不记分；连续两次仍无文本可询问是否放弃本题，但**不自动转录**成用户选择「这题我不会」 | 不把选项当回答、不替面试者补一句话、不伪造用户意图 |
| **示范作答写不出完整版本** | 按 `question_bank.json` 里该题 `anchors["4"]` 的四要素重建：结论 + 依据 + 可核对证据 + 代价与边界 | 不写「略 / 见参考答案」、不复制用户回答 |

## 2. 失败分级

| 级别 | 含义 | 处理 |
|---|---|---|
| `error` | 结构性不合格（缺章、题量越界、字数超限、引用编号断裂、面经状态与证据冲突、四级标题） | 必须修复并重跑脚本，否则不交付 |
| `warn` | 可接受但需知情（材料不足导致字数 7,000~8,000、单题偏短、来源未附链接） | 章 0 标注边界后可交付，交付话术里提一句 |
| `info` | 统计信息（有效字数、各章题量、来源条数） | 仅记录 |

## 3. 通用做法

- **部分结果**：能做的章节照做，做不了的章写清楚边界，不要因为一处缺数据就整体放弃。
- **不静默**：任何降级都要在章 0 留痕（「未检索到」「未核实」「领域题库未接入」「JD 信息不足」），让读文档的人知道哪些结论是推断。
- **优先顺序**：事实正确性 > 结构合规 > 覆盖度 > 文采。冲突时按此顺序牺牲后者。
