# 08 · 交互式模拟面试与回答评判

> 加载时机：步骤 8（仅交互版）。紧凑版不读本文件。
> 目标：在交付同一份文档之前真的「面」一次 —— 用对话框收集回答，按统一 rubric 评判，给每题的**正确示范作答**，把评判并进章 8。

## 1. 两种模式

| 模式 | 头部 `> 模式：` | 行为 | 章 8 |
|---|---|---|---|
| 交互版（默认） | `交互版` | 逐题弹对话框提问 → 采集回答 → 评判 → 并入文档 | 必须有 |
| 紧凑版 | `紧凑版` | 不提问，直接出准备文档 | 不得有 |

- 用户说「帮我准备面试 / 我要面试 X」且未明确要求「不要提问 / 直接出文档」→ 交互版。
- 用户明确要求跳过提问 → 紧凑版，章 0 标注「未进行模拟面试」，**不编造评判**。
- 模式一旦确定不中途切换；中途要求停止按 §6 降级。

## 2. 开局对话框（补问必填信息）

四项必填缺失时，**一次对话框问清所有缺失项，问完即停**，不边问边生成。

- 能查到的不要问：公司主体、公开 JD、公开面经由检索工具补齐；只把「工具查不到且必须知道」的列为问题。
- 一次对话框 ≤4 个问题，每题 2~4 个选项；需要长文本（如简历）时明确提示「在下方输入框粘贴」。
- 可选项（案例 / 作品集）缺失**不得追问**。
- 推断项不得写成事实，在章 0 标「待确认」。公司主体有歧义时把确认作为一个问题，不自行拍板。
- 上传简历时必须记录 `> 简历状态：` 三态（见 `01` §1、`03` §11），它决定章 4 的修改清单怎么写。

## 3. 出题：基础热身 → 按回答循序渐进（细则见 `09`、`10`）

- **首题**：按面试类型执行 `python scripts/pick_questions.py --level L1 --group <basics|behavior> --seed <种子>`；业务面从 L1 基础八股池抽、落成正文中带 `【基础八股】` 的章 3 题目，HR 面从 `behavior` 池抽行为入门题（不出技术细节）。把 `seed` / `pick_group` / `bank_id` 记入台账，脚本会复算。
- **后续每一轮由上一轮回答决定**：按 `09` §3 决策表选择 `追问 / 升档 / 降档 / 保持 / 试探性升档`。常规升档最多 +1 且由 ≥3 分触发；**同档连续追问 2 次、上一轮 2~3 分时改用 `probe` 换考点升一档**（`09` §3.1），避免全程卡在 L1；0~1 分不升档，改问同考点具体场景；追问与 probe 都必须引用上一轮回答原句并写清决策理由。升档换考点时优先用 `--tags <题域>` 从 `10` 命中的 JD 题域抽题。
- **轮数**：业务面 5~7 轮、HR 面 4~6 轮，独立主问 3~5 道；**连续追问 ≤2 次、全场追问 ≤4 次**（见 `rules.json`）。不得预先排好整场难度轨迹再提问；用户提前结束时按 §6 只保留已发生轮次。
- 每道主问必须能回指正文 Q 编号；追问沿用被追问轮的 `q_ref`。
- **提问对话框只给题干 + 场景**：不给参考答案、答题框架、评分标准、难度标签、优先级标签，也不点明考点。给答案或提前透露「这题升级了」都等于泄题，模拟失效。
- 每次对话框只问 1 题；题干后固定一句：

  > 请直接在下方输入框作答；答不上来可以选「这题我不会」。

- **固定四个选项（不得增减、不得改名、不得出现「口述作答」）**：

| 选项 | 台账 `option` | 含义 | 是否算回答 |
|---|---|---|---|
| 这题我不会 | `这题我不会` | 直接记 `answered=false`、0 分；**作答已结束**，立刻给本题的示范作答要点与改进口径，再进下一轮 | 是（唯一「选项即回答」） |
| 需要提示 | `需要提示` | 给 1 句不含结论的脚手架，重问同题，不新增轮次、不记分；用户随后在输入框写答案 | 否，必须有文本 |
| 直接作答 | `直接作答` | 在下方输入框写答案；无文本则重问同题 | 否，必须有文本 |
| 换一道题 | `换一道题` | 内部事件 `skip`：显式换同难度同题域的另一道题，**不要求先回答原题**；仍须写文本才算回答 | 否，必须有文本 |

- **选项不是回答本身**：除「这题我不会」外，只点了选项、没有任何文本 → 视为未作答，**重问同一题**，不新增轮次、不记分、不判达标（脚本 S27 会核对台账）。
- 用户把答案写在输入框 / 自由文本里，以该文本为**回答原文**；选项只作为状态记录进 `option` 字段。
- 「给一句提示再答」并入同一轮：提示写在题干补充里，台账 `hint_given` 可记一句，不新增 M 轮次。
- **作答之后**（不是提问时）才展示参考答案：选「这题我不会」或评分 ≤1 时，先给本题评判与 `**示范作答**`，再继续下一题；其余题的参考答案仍不提前展示。

## 4. 回答采集（interview-log.json）

每轮对话框返回后立即写一条，**不得事后补写、不得润色回答**。

```json
{
  "session_id": "demo-session-001",
  "mode": "interactive",
  "started_at": "2026-01-01",
  "pick_seed": "demo-seed-001",
  "pick_group": "basics",
  "turns": [
    {"id": "M1", "q_ref": "Q3-1", "round": 1, "followup_of": null,
     "level": "L1", "bank_id": "L1-B02", "topic": "Transformer 自注意力与 QKV",
     "option": "直接作答",
     "question": "…", "answer": "…", "answered": true,
     "score": 3, "verdict": "有依据缺代价", "gaps": ["…"], "fix": "…",
     "decision": {"action": "start", "based_on": null, "reason": "题库 L1 八股池随机首题"},
     "domain_ref": "通用八股；本地知识库无对应题号"}
  ]
}
```

- `answer` 必须是用户返回的原文；无文字 → `answer=""`、`answered=false`。
- `option` 必须是 §3 白名单四值之一；含「口述」或不在白名单 → 脚本 S27 判不合格。
- `score` / `verdict` / `level` / `decision` 在**看到回答之后**才写，不得先排好整场轨迹。
- `q_ref` 必须指向文档中真实存在的 Q 行；追问用 `followup_of` 指向被追问轮的 `id`。
- `level` / `bank_id` / `decision` 的完整约束见 `09` §5；追问的 `based_on` 必须是上一轮回答原文片段（≥8 字）且出现在追问题干里。
- **已知边界**：log 仍由模型按对话框结果转录，脚本只能验「文档与 log 一致」，不能证明对话真实发生过。彻底防伪造需对话框工具直写日志。

## 5. 评分 rubric（0~4）

| 分 | 档位 | 判定 |
|---|---|---|
| 0 | 未作答 | 无回答 / 选「这题我不会」/ 跳过 / 只选选项无文本 |
| 1 | 概念复述 | 只有名词没有结论，或结论自相矛盾 |
| 2 | 有结论无依据 | 结论先行但说不出为什么，或依据与结论无关 |
| 3 | 有依据缺代价 | 结论 + 原理 / 项目证据，但没讲边界、代价、替代方案，或答不上追问 |
| 4 | 完整可讲 | 结论 + 依据 + 可核对项目证据 + 代价与边界 + 经得住一次追问 |

- 追问单独记分；追问后仍答不清，首轮最高给 2 分。
- 评判必须**引用回答里的具体词句**说明得分理由，禁止「答得不错 / 理解到位」这类空话。
- 3 分及以上仍要指出缺的那一块；0~1 分必须给可替换的完整口径。
- 只评价回答，不评价用户本人，不写性格判断。

### 5.1 每题都要给「没有问题的真实回答」

无论得分高低，章 8 每组末尾都要有 `**示范作答**`：

- 写这题**在已知材料与假设下可用的示范作答**，不是答题框架、不是对回答的点评：结论句 → 编号分点 → 可核对证据（项目 / 教学示例 / 题号 / 日志 / 评测集）→ 代价与边界 / 替代方案；**教学代码不得写成第一人称履历**（`04` §7）。
- ≥100 有效字、可直接朗读；不得写「略 / 见参考答案 / 同上」，不得与用户回答雷同。
- 0~1 分或选「这题我不会」时，这段就是面试者最该背下来的版本，可顺带点出与刚才回答差在哪一步。
- 示范作答与正文该题的 `**参考答案**` 口径一致，但按模拟面试的题干重写一遍，不整段复制。

## 6. 降级与中断

| 场景 | 做什么 | 不做什么 |
|---|---|---|
| 用户中途说「别问了，直接出文档」 | 已发生轮次照实保留，`ended_reason=user_stopped`，章 8 注明「用户提前结束，最高难度 Lx」；豁免目标轮数与「必须升到 L3」 | 不删已产生的回答、**不补写未发生轮次**、不伪造升档 |
| 选「这题我不会」 | 记 0 分，给本题示范作答与改进口径，按决策表降档或改问场景 | 不追问「再想想」凑分、不把 0 分写成「接近达标」 |
| 只选了选项、没有文本 | 重问同题，不新增轮次、不记分 | 不把选项当成回答、不替用户补一句话 |
| 连续 2 题答不上来 | 降一档难度，改问同考点的具体场景题，仍记分 | 不换送分题伪装达标 |
| 同档连续追问 2 次仍是 2~3 分 | 按 `09` §3.1 用 `probe` 换考点升一档，题干引用上一轮原句、reason 写明「试探」 | 不继续原地追问、不因分数低就无视「慢慢变难」 |
| 对话框能力不可用 | 切紧凑版，章 0 注明「交互不可用」 | 不用纯文本提问冒充对话框、不虚构回答 |
| 用户要求看答案 | 先给该题评判、改进口径与示范作答，再继续下一题 | 不提前展示其余题的参考答案 |
| 题库 / 抽题脚本不可用 | 首轮 `bank_id=""`，章 8 注明「未按题库随机起手」，其余照跑 | 不编造 seed 与 bank_id |
| 全程 0~1 分，难度上不去 | 保持 L1~L2 的具体场景题，章 8 如实写「未进入 L3」 | 不为「看起来循序渐进」硬升难度、不换送分题 |

## 7. 写入章 8

格式见 `03-output-spec.md` §9。要点：

- 每组必须含「回答 / 评分 / 失分点 / 改进口径 / 考点索引 / **示范作答**」六项，M 行还要带 **L1~L4 难度标签**，缺一不可。
- 章首给**难度轨迹表**（轮次 / 难度 / 触发动作 / 得分），与台账 `level` / `decision` 逐行一致。
- 回答原文照抄，不润色、不缩写；超过 200 字可摘录，但须标「节选」并保留关键句。
- 末尾给**总评表**：题号 / 得分 / 最该补的一件事，补一句「本场最高难度 Lx，下一场建议从 Ly 起手」，再给 3 条下轮优先复习项（引用 `04` 的真实题号）。
- 评判与 `interview-log.json` 逐条一致，脚本会交叉校验。

## 8. 反模式

- 把参考答案、答题框架一起塞进提问对话框（泄题）；
- **选项里出现「我要口述作答 / 口述回答」这类占位项**，或自造第五个选项；
- 只选了选项没写文本就算作有效回答并给分；
- 替面试者把回答补完整，或把没说过的证据算进得分；
- 未作答判「达标」，或全员 4 分；
- 章 8 只批评不示范，或把示范作答写成「见参考答案」；
- 先写好章 8 再回头提问，或先排好难度轨迹再装作按回答调整；
- 无视上一轮低分硬升难度，或追问题干不引用回答原句（「结合上面继续问」不算深入）；
- 用 `advance` 伪装低分升档，或 `probe` 不引用原句 / 不写「试探」理由 / 不换考点 / 连着用；
- 把难度标签 / 「这题升级了」写进提问对话框（泄题）；
- 把模拟面试记录上传公开仓库 —— 个人作答与错题记录只留本地，不进 git。
