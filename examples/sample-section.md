**Q3-1｜【基础八股】Transformer 自注意力为什么是平方复杂度**
**考察意图**：看能否从公式推出复杂度，而不是背结论。
**答题框架**：1. QKV 与缩放点积 2. 复杂度来源 3. 长上下文的缓解手段。
**参考答案**：**结论先行**：注意力要对序列里每一对位置算一次相关性，所以计算与显存随长度按 n² 增长。1. 依据来自缩放点积 softmax(QKᵀ/√d)V，QKᵀ 本身就是 n×n 矩阵，除以根号 d 是为了让点积量级不随维度膨胀、softmax 不饱和。2. 证据：多头只是把 d 切成 h 份并行，并不改变 n×n；KV Cache 只省掉推理时的重复计算，训练时仍然要算满。3. 代价与边界：稀疏 / 线性注意力能压复杂度，代价是长程依赖近似误差；替代方案是分块 + 检索式召回，边界是跨块全局推理会变弱。
**优先级**：🔴 必背

**Q3-4｜怎么判断该用 Agent 还是 Workflow 【面经高频】**
**考察意图**：看能否按不确定性做选型，而不是逢场景就上 Agent。
**答题框架**：1. 路径是否确定 2. 是否需要运行时决策 3. 成本与可评估性 4. 失败代价。
**参考答案**：**结论先行**：下一步由代码还是模型决定，是唯一的判断线。1. 依据：路径可枚举、规则可维护时用 Workflow，延迟与成本都可控；只有决策点无法预先枚举、且多步工具会改变外部状态时才上 Agent。2. 证据：这个演示实现里把固定审批流保持为 Workflow，只把故障定位做成 ReAct loop，对应 code/01_minimal_react_agent.py 的观察回填，并用日志回放定位过死循环（教学示例，非本人履历）。3. 代价与边界：Agent 带来错误链沿轨迹传播与评估成本；替代方案是「Workflow + 少数模型决策节点」，边界是高危动作仍要交给状态机，失败退化为人工确认。
**优先级**：🔴 必背

## 6｜Gap 质疑题
**Q6-1｜你没有生产环境 Agent 经验，凭什么能胜任**
**考察意图**：看是否承认差距并给出可迁移证据，而不是只表决心。
**答题框架**：1. 承认差距 2. 可迁移能力 + 证据 3. 拟补足计划（有证据才写已完成） 4. 动机与岗位价值。
**参考答案**：**结论先行**：差距在生产化经验，不在闭环原理。1. 承认：确实没有线上多租户 Agent 的运维经历。2. 可迁移证据：演示实现里 code/01_minimal_react_agent.py 与 code/09_guardrails.py 覆盖了最小 loop 五件套、幂等与停止条件，并用 code/08_evaluator.py 跑过回归（教学示例，非本人履历）。3. 拟补足计划：补 checkpoint 恢复与 trace 回放，把失败定位从整段猜测缩到具体一步；本项尚未落地，待本人确认。4. 代价与边界：本地模拟没有真实流量与权限体系，这部分只能靠入职后的线上轮值补，替代方案是先在影子流量里做只读回放。可替换措辞：「我没有 X，但我做过与之同构的 Y，证据是 Z」。
